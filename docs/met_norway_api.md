## [NAME](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
[NAME](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
Locationforecast - Weather forecasts for any location on earth

## [DESCRIPTION](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
[DESCRIPTION](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
This service delivers weather forecasts for any given coordinate for the next nine days, in JSON and (deprecated) XML formats. There are several variants with different parameters, with most data for the Nordic region.
For up-to-date precipitation forecasts, see our Nowcast service which is updated every five minures. The service is not suitable for forecasts above ground level. For aviation purposes, please see our IsobaricGRIB service.
For more information see the [Locationforecast data model](https://docs.api.met.no/doc/locationforecast/datamodel.html).

## [DATA FORMATS](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
[DATA FORMATS](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)

### [JSON format and variables](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
[JSON format and variables](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
Version 2.0 defaults to JSON format for data. For an explanation of the various variables, see the [Datamodel](https://api.met.no/doc/locationforecast/datamodel) documentation. The JSON format is described in the [General Forecast Format](https://api.met.no/doc/ForecastJSON) documentation.

### [XML format](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
[XML format](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
For those who want to continue using their existing clients with a minimum of changes, you can also continue using the old XML format. This must be accessed via the classic method, like this:

```
classic
```


```
[https://api.met.no/weatherapi/locationforecast/2.0/classic?lat=59.93&lon=10.72&altitude=90](https://api.met.no/weatherapi/locationforecast/2.0/classic?lat=59.93&lon=10.72&altitude=90)
```

[https://api.met.no/weatherapi/locationforecast/2.0/classic?lat=59.93&lon=10.72&altitude=90](https://api.met.no/weatherapi/locationforecast/2.0/classic?lat=59.93&lon=10.72&altitude=90)

```
https://api.met.no/weatherapi/locationforecast/2.0/classic?lat=59.93&lon=10.72&altitude=90
```

Note that the msi parameter is now called altitude in 2.0.

```
msi
```


```
altitude
```

The XML format is considered legacy, and as similar to 1.9 as possible except for additional time periods and the XML Schema URI. Future enhancements will primarily be added to the JSON format.
Also, some elements will be removed when version 1.9 is terminated, including the following elements:

```
<temperatureProbability unit="probabilitycode" value="0"/> <windProbability unit="probabilitycode" value="0"/> <symbolProbability unit="probabilitycode" value="1"/>
```

### [Weather icons](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
[Weather icons](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
Along with the new JSON format we also have a new set of weather icons, in PNG, SVG and PDF formats. They can be downloaded from [GitHub](https://github.com/metno/weathericons/).
The filename (minus extension) corresponds to the symbol_code in the JSON format, including variations for day, night and polar day. This means there is no need for calculations or fetching data from the Sunrise service in order to present the correct weather icons. This has also been added to the XML as an attribute code to the symbol element:

```
symbol_code
```


```
code
```


```
symbol
```


```
<symbol id="PartlyCloud" number="3" code="partlycloudy_day"></symbol>
```

Note: There is a typing error in lightssleetshowersandthunder and lightssnowshowersandthunder (extra "s" after "light"). Unfortunately, correcting this would mean breaking existing applications, so it has been postponed to the next version of weathericon/locationforecast.

```
lightssleetshowersandthunder
```


```
lightssnowshowersandthunder
```


#### [Wind symbols](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
[Wind symbols](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
Wind direction denote where the wind is coming from, where 0° is north, 90° east, etc. For GUI applications use we suggest using arrows, like these:
[⬇](https://api.met.no/weatherapi/locationforecast/2.0/documentation)
0° (north)
[⬅](https://api.met.no/weatherapi/locationforecast/2.0/documentation)
90° (east)
[⬆](https://api.met.no/weatherapi/locationforecast/2.0/documentation)
180° (south)
[➡](https://api.met.no/weatherapi/locationforecast/2.0/documentation)

[Methods](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
[/complete](https://api.met.no/weatherapi/locationforecast/2.0/documentation)
JSON forecast with all values. This will shortly be expanded with probabilities, so that each variable will be repeated for a set of percentiles.
[/compact](https://api.met.no/weatherapi/locationforecast/2.0/documentation)
A shorter version with only the most used parameters (if you feel something is missing, please let us know)
[/classic](https://api.met.no/weatherapi/locationforecast/2.0/documentation)
The old XML format, now considered legacy. It matches the output of version 1.9 closely, but includes more time periods. Future new parameters will not be added to this version.

### [Parameters](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
[Parameters](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
[lat](https://api.met.no/weatherapi/locationforecast/2.0/documentation)
latitude in decimal degrees, mandatory
[lon](https://api.met.no/weatherapi/locationforecast/2.0/documentation)
longtitude in decimal degrees, mandatory
[altitude](https://api.met.no/weatherapi/locationforecast/2.0/documentation)
Ground surface height above (or sometimes below) sea level in whole meters (integers). Optional but recommended for precise temperature values. When missing the internal topography model is used for temperature correction, which is rather course and may be incorrect in hilly terrain.
Note that this is the altitude of the ground surface! You cannot use this to ask for atmospheric predictions, e.g. for aviation purposes.

## [AUTHENTICATION](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
[AUTHENTICATION](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
Due to poor adherence to the identification requirements in the Terms of Service, we have implemented more stringent checks on sending a unique identifier in the User-Agent header. Any requests with a prohibited or missing User-Agent will receive a 403 Forbidden error.
Examples of banned User-Agents include:
- okhttp
- Dalvik
- fhttp
- Java

## [HISTORICAL FORECASTS](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
[HISTORICAL FORECASTS](https://api.met.no/weatherapi/locationforecast/2.0/documentation#___top)
While we only serve current forecasts via the API, you can find historical forecast model data in NetCDF format on [https://thredds.met.no/thredds/metno.html](https://thredds.met.no/thredds/metno.html).
Due to licensing issues we can only distribute model data for the Nordic and Arctic regions. For global model data, please contact ECMWF.
